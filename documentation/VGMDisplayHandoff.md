## Review and test procedure

1. Download the four named assets to an empty folder. Verify all of them before extracting or installing (Linux, GNU coreutils):

   ```sh
   sha256sum -c <<'SHA256'
   097dc0bd407f39b558e9baa4ad86c371bdfbfed276a223c862aa1545ecc8d71c  VGM.Display.0.3.1.uf2
   ad46b8e615b8d1df771614a22035e19463cbd1ceb287911d570c2807f34caef6  VGM.Display.0.3.1.tar.gz
   f6f6b121216970364446f7419727ca0159d5488c849b6f56ab83eaf1ee1722af  desktop-settings-v0.2.fap
   22e9393942cf750db527c27ae9726b438111f30acf79af60201722c7689adaec  hybridus-desktop-settings-0.2-source.zip
   SHA256
   ```

2. For source review, compare the VGM tree to [Flipper Devices VGM 0.1.0, commit `f18ad44`](https://github.com/flipperdevices/video-game-module/tree/f18ad4481ef04449aaae55a4d5556923effef276). Review the FAP ZIP's `NOTICE.md`, `README.md` and `evidence/RESULT.md` for provenance and prior test results; the archive's pre-release notes predate the owner's later device confirmation. If you already have the exact Hybridus host image, run the supplied `verify-host.py` as documented there to check imports without flashing. The missing exports are `hybridus_vgm_settings_get`, `hybridus_vgm_settings_set`, `hybridus_vgm_settings_save`, `hybridus_color_get` and `hybridus_color_set`. API number alone does not establish compatibility, and the ZIP does not reproduce the complete host or end-to-end stack.
3. For optional VGM bench testing, use the [official custom firmware installation guide](https://docs.flipper.net/zero/video-game-module/custom-firmware): copy the verified UF2 to the Flipper microSD, then select **Install Firmware from File** in Video Game Module Tool; or install directly on the module over USB-C in BOOTSEL mode. This changes the module, not Flipper Zero firmware. Verify mirror output, side panels and invert. Use the [official module firmware flow](https://docs.flipper.net/zero/video-game-module/firmware-update) to restore stock firmware if needed.
4. Test the FAP only on the matching Hybridus F7 host with the required exports. Back up any existing Desktop Settings FAP; install the verified binary as `/ext/apps/assets/desktop_settings.fap` on that host. Check Settings → Desktop opens and exits normally, then check RGB, invert, bezel, sync and Save separately. Check Flipper-side saving and VGM state after a full power cycle independently; a host Save message is not a module acknowledgment. Do not install this FAP as a drop-in for stock Unleashed.

**Evidence and limits.** The published UF2 was previously reproduced byte for byte locally. The device owner reported successful display output, side panels and inversion on a 1920×1080 monitor (monitor resolution, not measured output timing), and reported that Desktop Settings 0.2 worked on their device. Those reports do not establish per-control end-to-end behavior, RGB synchronization, persistence after power loss, or compatibility with Unleashed `dev`. The prior FAP import check covered 167 imports against the exact Hybridus host; the ZIP supplies declarations, not the absent implementations. This handoff adds no firmware code and runs no new firmware/hardware build or install.

That is not a blanket license, an assignment, or confirmation that Unleashed may import or redistribute all RP2040 source, schemas, assets or binaries.
- The FAP archive includes GPLv3 text for the Unleashed-derived material and identifies GPL-3.0-only additions in `NOTICE.md`. The separately authorized publication of the binary does not establish complete corresponding source or supply rights to the missing host code. Review that separately before bundling the FAP. The contributor offers their own contribution at no charge and is willing to forgo personal credit for that contribution; this does not transfer or remove any third-party rights or notices.
- A firmware-code PR would need a verified VGM capability signal and a host-side settings path in `dev`'s existing UART RPC screen stream. `RpcOwnerUart` alone does not identify a VGM. Begin with manual RGB565, invert and bezel; leave stock/unknown modules, USB and BLE on standard frames. Test both frame forms, reconnect, and same-base F7 payload size before proposing a merge. The [PR discussion](https://github.com/DarkFlippers/unleashed-firmware/pull/1245) records the candidate HVG2 fixture and code entry points. No unbuildable host patch or foreign firmware is included in this change.
