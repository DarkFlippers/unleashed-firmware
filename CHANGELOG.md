## Main changes
- Current API: 88.20
- RFID: **New T5577 app - read a T5577's blocks, save them, and write them back** - the Flipper could write a T5577 but never read one, so there was no way to see what a tag held, keep a copy of it, or put a copy back. Read Tag works out how the tag reads and then reads every block of both pages; what comes back can be saved as a `.t5577` dump, looked over a page at a time with block 0 spelled out in the terms the chip reads it in, renamed, deleted, or written to a tag again. A block that was never read is kept apart from a block holding zero, because a protected chip answers nothing and a partial dump is the normal case rather than the exception: the dump shows them as dashes rather than as zeroes, and a write skips them. A read that could not get the whole tag says so instead of chiming, since a protected chip going quiet part way through is the ordinary way to find out there is a password left to find. A write goes data blocks first and block 0 last - block 0 decides how the chip talks, and block 7 is the password it will start asking for - and the tag is then read back through the ordinary read path and compared, so "Written!" means the tag said so. Page 1 goes back as well - blocks 1 to 3 of it, the ones a Proxmark3 restore writes - because they hold the traceability data the chip was made with, and a copy that leaves it behind is not the same tag. The dump format is documented and parsed in `lib`, so a dump outlives the app that wrote it (by @mishamyte)
- RFID: **The firmware can read a T5577 block, which is what the app is built on** - a tag's answer repeats with no frame marker, so a read cannot tell where a word begins. Block 0 settles it for itself, since it describes the modulation and bit rate its own answer arrived in, but every other block needs an anchor from outside - and the bit offset block 0 was found at is not one, because where a decoded run starts moves from read to read. Time is: the read window opens a fixed interval after the command and the tag's bit clock is divided from the field the Flipper itself generates, so the same tag bit arrives at the same time in every read, tracking the clock to within 10 us over 147 ms. Getting there needed the capture timed from the instant the window opens rather than from the first run that decoded, the settle timed to the microsecond rather than to a tick - a tick of slop is two bits of phase at RF/64, and it was moving the answer by three - and a run ended as soon as a bit arrives more than a quarter of a bit period away from where the bit before it puts the next one, since a decoder that gains or loses a bit leaves everything after it agreeing with itself while sitting a bit away from where the time says it is. An erased block is the one case needing care either way: the tag sends the same waveform for 00000000 and FFFFFFFF, and only the alignment tells them apart (by @mishamyte)
- RFID: **Wipe T5577 and Clear T5577 Password now check the tag instead of assuming** - both used to be blind. The wipe watched for six seconds to see whether the tag still read as anything and called silence a success; Clear Password announced "Success!" whichever password it had tried, including when none of them fit. Both now write a block and read it back, so the verdict is the tag's own answer, and both show what they are doing while they work. The wipe writes its eight blocks one at a time behind a progress bar and leaves Proxmark3's own blank configuration, so a tag wiped by either tool looks the same to the other; when it cannot confirm, it says whether the tag went quiet or answered with something else, and points at Clear Password for the former, which is what a password looks like from here. Clear Password tries the tag as an unprotected one first, three times, then the custom password, then the shipped list - stopping at whichever works. Stopping matters: every attempt after the tag is already open sends a password frame that an open tag reads off the wrong bit positions, and a third of the list would set block 0's lock bit permanently if it did. It no longer writes the password block at all, since clearing the password bit in the configuration is what opens the tag. The honest cost is time - a password that is not in the list now takes about a minute and a half, where before it took ten seconds and then claimed success regardless - so the screen names the candidate it is on and Back stops it at once. Getting the read to work at all needed the reader's own comparator offset measured and subtracted: it reports every high half-bit longer than it is by 50-70 us, which is a fifth of a half-bit at RF/64 and half of one at RF/32, and without that correction the shorter rates do not decode (by @mishamyte)

### What `e`, ` `, `c` means? What I need to download if I don't want to use Web updater?

What build I should download and what this name means - `flipper-z-f7-update-(version)(e / c).tgz` ? <br>
`flipper-z` = for Flipper Zero device<br>
`f7` = Hardware version - same for all flipper zero devices<br>
`update` = Update package, contains updater, all assets (plugins, IR libs, etc.), and firmware itself<br>
`(version)` = Firmware version<br>
